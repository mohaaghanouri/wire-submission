02 / SYSTEM CONTEXT

A static app, a database, and one agent session per run.

The app reads the database directly. Each run is one managed agent session that fetches sources and writes its results back.

NO BACKEND

The app reads the database directly

Sign-in and access rules decide what each member sees. There is no server of mine to run or patch.

ONE SESSION PER RUN

Every run is pinned

Run control starts a managed session with fixed prompt and code versions and a spending cap. Any edition traces to exactly what wrote it.

TWO CLOCKS

Weekly judgment, daily checks

The judged run starts every Monday. A code-only job checks tracked pages every morning and can alert between editions.

Trade-offWith no backend, the database access rules are the whole security model, so they have their own tests.

03 / DATA FLOW

One weekly run, start to finish.

Code handles the repeatable steps, Haiku reads what the filter keeps, and one Opus agent decides what matters.

CodeOne model callAgentWriters
WHO IS KEY

The layer below the leaders

Labs through their own channels, and the researchers whose papers and code come first. Leaders already speak through the lab. Each person has a stated reason; ex-lab startups are labs of their own.

ONE PERSON, MANY ACCOUNTS

Linked only with proof

An X handle, GitHub account or arXiv name joins a person only if their own page shows it, never by name. Official, personal and press sources are labelled apart.

COVERAGE

Few sources, done well

Lab channels, arXiv, GitHub, Hugging Face, talks, and X through Apify. LinkedIn and anything behind a login are out. A source that fails twice or goes silent is flagged.

NOISE

Dropped by shape, in code

Replies, reposts, duplicates and stale posts go before any model reads them, each with a reason a curator can overrule. There is no topic rule, so an unexpected subject still gets through.

One card per itemEvery kept item is read once into the same short shape: what it says, who and what it names, and its claims, each with an exact quote. Everything after works from cards: the analyst scans and searches them, links them to the register and to past stories, and cites their quotes as evidence.
RejectedA model triaging every item instead of the filter: it recreates the reading cost the filter exists to cut.

04 / MODEL CHOICES

An agent only where the next step depends on what it reads.

Three agents in total. Anything with a right answer runs as code.

CODE

Anything with a right answer

  • Fetching and filtering
  • Quotes and numbers checked
  • Each edition checked
  • Daily change alerts

Cheap, exact and testable.

ONE MODEL CALL

Reading at scale

  • Haiku summarises every kept item
  • Sonnet reads long documents
  • Haiku checks quote support
  • Opus ranks the stories

Sonnet summaries moved the picks no more than a second rater did, so Haiku reads first.

AGENT

Decisions that branch

  • Opus decides what matters
  • It chooses when to read deeper
  • It sends a scout for a source
  • Sonnet writers compose, then review

The strongest model sits where a wrong call costs most.

WHAT COUNTS AS MATERIAL

Every story answers
a question.

Investment: inference cost, memory, compute, power, new labs, moats.
AI team: evaluation, open models, pipelines, tooling.
Plus neutral triggers, and at most two “unexpected” a week.

ACTHigh score
Strong evidence
WATCHGood score
Moderate evidence
THE THREE AGENTS
ANALYST · OPUS 5.5

Coordinates the run

Runs the pipeline’s own tools in its sandbox, reads cards and past weeks, and stores the stories. The only agent that can call the other two.

SCOUT · SONNET 5

Finds one primary source

Web search and fetch only, with no write access. It answers one question from the analyst and returns the source.

WRITER · SONNET 5

Writes one edition

Gets one team’s stored facts and the report skill, and writes the HTML. Called again with the rubric, it reviews both editions.

When a step failsA failed summary is retried once. A story that fails its checks is fixed once, then cut. A failed ranking leaves scores marked provisional. A claim with no primary source sends a scout.
RejectedAn agent per document: much of its reading went on items later dropped. No agent at all: the next step depends on what was just read.

06 / QUALITY & GROUNDING

What I measured, and what it changed.

Every label is a separate model’s, given blind, and every figure has its sample size. Checks in code block fabricated claims in every run.

How I evaluateOutside the product, in Claude Code. A separate model that no pipeline stage uses labels samples, judges picks blind, and compares the old and new versions week by week over the replay. Its labels never reach the pipeline. The repository’s evaluation record gives each figure with its 95% interval.
THE FILTER

Does it keep what matters?

30/30items the labeller kept, the filter kept too

An audit of 106 dropped items found 7 worth keeping, a system card among them, and two rules changed. Precision is 0.57: the analyst drops the rest.

THE SUMMARIES

Is the cheap model enough?

19/24picks unchanged on Sonnet’s cards, the same as a second rater on Haiku’s

Sonnet wrote the best long summary in 12 of 20, but it did not change the picks. Haiku reads first; Sonnet reads deep on request.

THE CHECKS

Do false stories get through?

20/20planted false stories refused, and the clean control passes

The set found a gap: a number with a unit, like “2M context”, skipped the number check. Fixed.

THE SCORE

Does it mean something?

22/24of the analyst’s top picks rated useful; 15 were in the rater’s own top 3

The judge preferred the old version’s alerts 28 times to 19. After recalibration, 17 of those 28 now alert.

WHAT GETS CHECKED IN EVERY RUN
01

Before a story is stored

Every quote and number is found in a source, and at least one quote supports the claim. A match shows the source said it, not that it is true.

02

Before an edition is released

Every citation and figure traces to a stored story; nothing loads from outside.

03

Evidence has a ceiling

Press coverage alone is weak evidence, whatever the analyst thinks of it.

GROUND TRUTH

Model labels now, the teams’ labels next.

I could not label by hand in five days, so a separate model labels blind. That shows the system is consistent, not that it is right, and the labeller shares a model family with the pipeline.

One outside check failed: the contributor score against OpenAlex output, Spearman −0.27 over 15 people. OpenAlex counts publishing, not originating, so it was the wrong check. The golden set on page 09 replaces the model labels with the teams’ own judgment.

07 / RELIABILITY & SECURITY

Failures are recorded, and the run closes partial.

Progress and source health live in the database, outside the session, so a failed run can be resumed where it stopped.

WHEN SOMETHING FAILS
FailureWhat happens
A source failsRecorded; the run closes partial and the edition names the gap
The session idles or runs out of budgetA watchdog closes the run within minutes; a hung session is closed at a hard time ceiling
A curator resumes a runIt restarts at the last finished stage, within the remaining budget
An edition fails its checksIt is not released
The Claude platform is downThe run is recorded as failed; a curator resumes it when the platform is back. Page 10 adds a second provider
ACCESS

Readers are not operators.

Invite-only sign-in, reader and curator roles, and database guards on what the pipeline may change. Fetched pages are read by tool-less model calls and marked untrusted.

GENERATED HTML

Editions run scripts but carry no sign-in.

They run sandboxed, cannot load anything from outside, and never see the reader’s session.

What I watchA cost for every run, and a trace once its session is imported. Failed runs and newly failing sources raise an operator alert in the app, ready to post to Slack.
RejectedMy own workers and queue on the plain API: I would own every loop, retry and tool call. A workflow framework would be a second orchestrator.

08 / COST & HOW I WORKED

What a run costs, and the loop that built it.

The analyst and the writers are 79% of a $12.52 run. Four replays decided what stayed.

WHERE THE MONEY GOES
$12.52One weekly run at list prices, 68 minutes. The session is capped at $15.
Analyst, Opus$5.24
Writers and reviewer, Sonnet$4.65
Cards, ranking, support checks$1.66
Scouts, Sonnet$0.88
WorkflowCost
Daily change checkNo model cost; 42 seconds on GitHub Actions
Replay of 12 weeks$14.15 of API; judging ran as Claude Code subagents on the subscription
Whole buildAbout €100 on the Anthropic API and a €19 Apify plan for X: a little over the €100 budget

Tokens per weekly run: 17.6 million read, most of it cached context the agents re-read, and 182,000 written. Reading 180 items costs $0.62. Cost set three choices: Haiku reads first, daily alerts are code, and live runs never batch.

HOW I WORKED

I set the direction and approved every deploy, migration and paid run. Claude Code wrote the code from a written plan, and an independent review checked every change. A separate model did all the labelling and judging.

The core went through four versions in a week. Each replay showed what to cut: too many agents, too much reading, reports that read like an audit trail.

What the agents verifiedWhile building: tests run by hand before every deploy (code, database, browser), numbered review rounds, planted false stories. In every run: quotes, numbers, tickers, support, the edition contract, a rubric review.
What worksThe weekly run end to end, daily change checks, two editions, resuming a failed run, the watchdog, and the app with feedback.
WHERE THE LOOP BROKE
  1. The filter dropped a system card. Auditing what it threw away changed two rules.
  2. The support check was not repeatable. A real story failed on rerun and was cut.
  3. The new version under-alerted. The judge preferred the old alerts, so I recalibrated.
  4. No browser in the sandbox. A screenshot script exists, but no run executes it.

09 / FUTURE WORK · PRODUCT

What I would build next.

The first four change how Wire learns and what it costs. The rest change what it does for an analyst on Monday morning.

01GOLDEN SET

Learn from the teams

TodayEvery label so far is a model’s.

NextSit with each team and collect the stories they found valuable. Tune the instructions, models and scoring against that set, and score on weeks it has not seen.

A session per team, then ½ day
02MARKET DATA

Tie stories to price moves

TodayWire does not see prices. DeepSeek’s cost was public a month before the market moved.

NextPull daily prices for every tracked listed company from a market-data API such as Alpaca, back through the history. Match each past story to what the stock did next: grade old calls, then tune the scoring for new ones.

3–4 days
03FEEDBACK

Make feedback easy, and a game

TodayReaders can vote and comment. Nothing reads it.

NextAdd voice notes on any story. Keep a leaderboard and reward the most useful feedback each month. Every note feeds the golden set.

1–2 days
04COST

Run on a subscription, not the API

TodayEvery run pays per token.

NextRun the same prompts, skills and checks as a Claude skill or plugin, as ChatGPT agents, or as headless Claude Code on the plan we already pay for. The replay already ran its judging stages this way; logging is the part to add.

2–3 days
05PORTFOLIO

Alerts tied to positions

TodayAlert rules do not read position sizes.

NextGive the alert rules BIT’s holdings, and alert on new evidence about any position above 5%.

About 1 day
06DELIVERY

Push alerts to readers

TodayAlerts wait in the app, and a story can be a week old.

NextPost alerts to a readers’ Slack channel the day they fire, and let an urgent one start a mid-week run.

½ day
07COVERAGE

Find sources before they matter

TodaySources are added by hand.

NextWhen stories keep citing a site Wire does not track, add it. Turn recurring names into trial sources, and print each week’s known gaps.

2 days
08SPLIT BY TEAM

Each team gets its own Wire

TodayBoth editions read one register and one set of prompts. A curator’s switch applies to everyone; prompts change only by deploy.

NextWhen the golden set shows how the teams differ, give each its own sources and prompt: investment follows the chips, memory, hosting and power behind lab news; AI follows what is worth testing. Each team edits its part in the app, with every edit versioned. Shared facts stay in one store, so the editions still agree.

About 1½ weeks
Not nextCredit risk at AI-infrastructure borrowers is the live bear case. Neither lab news nor share prices show it; that needs credit data.
